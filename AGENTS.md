# Инструкции для агентов

Сравнение ежемесячной платы за жилищные и коммунальные услуги для одной и той же квартиры в шести городах: Ереван, Тбилиси, Белград, Варшава, Лиссабон, Берлин. Продуктовая спецификация — [issue #18](https://github.com/Anwert/utility-bills-compare/issues/18), карта решений — [issue #1](https://github.com/Anwert/utility-bills-compare/issues/1). Словарь терминов — `GLOSSARY.md`. Имена в коде английские, тексты для человека русские.

## Стек и почему он такой

- **Python 3.12** — адаптеры, конвейер и расчёт. Прототипы источников были на Python, для HTML/PDF есть зрелые библиотеки, GitHub Actions ставит этот рантайм без сборки фронтенда.
- **Статический HTML/CSS/vanilla JS без сборки** — сайт на GitHub Pages. Так страница быстро открывается с телефона и в ней нечему сломаться на шаге сборки. Сайт читает JSON контракта `CityMonth` и не импортирует Python.
- **pytest** — тесты. **ruff** — линтер и форматтер.

Зависимости и команды — в `pyproject.toml`. Новая библиотека добавляется туда, а не ставится «в обход» в workflow.

## Скрипты-прототипы (PoC) источников не лежат в этом репозитории

Скрипты-прототипы (PoC) источников не лежат в этом репозитории. Их запускали 24.11.2026 в песочнице; в тикетах есть URL, формат страницы, значения на эту дату и, в комментариях, код как справка. Адаптер пишется заново: описание в тикете, сохранённый образец в `tests/fixtures/`, тест на публичный метод `collect`. Код прототипа в репозиторий не копировать и не импортировать.

Адаптер тарифа, курса или градусо-суток заполняет `AdapterOutput.records`. Адаптер объявлений заполняет `AdapterOutput.candidates` (`BuildingCandidate`), а не нормализованные записи. Классификатор (`ubc.houses.pin_houses`) потом пишет `PinnedHouse`: слова сайта и пороги он берёт из `house_rules` города, новое слово добавляется туда, а не в код. Фразы в тексте объявления узнаёт `listing_text.py`; что они значат, тоже решают `house_rules`. Адаптер не знает про ячейки и расчёт.

Один протокол `Adapter.collect(CollectContext)` и один реестр. `ctx.source` — это `SourceConfig` для тарифа, курса и градусо-суток и `ListingSite` для объявлений. У сайта объявлений нет вида, надёжности и приоритета, поэтому подменять его фальшивым `SourceConfig` не нужно: тарифный адаптер читает конфиг через `require_source`, адаптер объявлений — через `require_listing`. `ctx.period` — месяц сбора (`YearMonth`, первый день в `period.first_day`). `collect_contexts` собирает эти контексты из конфигурации города.

## Правила TDD

Красный → зелёный → рефакторинг.

Тест проверяет внешнее поведение через публичный интерфейс модуля, не внутренности (приватные функции, порядок строк в файле, текст исключения сверх того, что нужно вызывающему).

Три тестовых шва из #18:

- **(a)** расчёт месячной платы ячейки на фикстурах нормализованных данных;
- **(b)** каждый адаптер на сохранённых HTML/PDF/JSON возвращает ожидаемые нормализованные записи (объявления — кандидатов домов);
- **(c)** политика выбора источника и уведомлений.

Сеть в тестах запрещена. Для шва (b) ответ модели, если он когда-нибудь понадобится, подменяется сохранённым файлом. Проверка схемы при загрузке — не шов, а защита: `ValidationError` и `ConfigError` роняют команду.

## Как добавить адаптер

1. Сохранить образец страницы в `tests/fixtures/<имя>/` и прописать URL в `manifest.json`. Для страницы, которая пустая без JavaScript, сохранять уже отрисованный DOM. Для PDF рядом положить `.txt`, если в CI нет poppler: `FixtureFetcher.pdf_to_text` берёт его.
2. Написать падающий тест: `FixtureFetcher` + `get_adapter(...).collect(CollectContext(city, period, fetcher, source))` и ожидаемые поля записи или кандидата. `period` — `YearMonth.parse("YYYY-MM")`.
3. Реализовать модуль по образцу `ubc/adapters/example_html.py`. В конце модуля — `register_adapter(...)`. Добавить строку в `ADAPTER_MODULES`.
4. Дописать источник в `data/cities/<город>.json` в список статьи (или в `fx_sources` / `hdd_sources` / `listing_sites`).

Пример источника в статье (в файлах городов таких записей пока нет):

```json
{
  "id": "yerevan_waste_arlis",
  "adapter": "yerevan_waste",
  "kind": "official",
  "priority": 0,
  "enabled": true,
  "reliability": "official",
  "settings": {"url": "https://www.arlis.am/hy/acts/219208"}
}
```

Сбор за обслуживание: сначала из объявления, потом `class_fees` города (сбор другого реального дома этого класса с адресом, датой и ссылкой), потом официальная ставка. Протоколы собраний содержат паспортные данные жильцов: в `data/raw` и фикстуры их не класть, ссылка ведёт на страницу дома.

У сайта объявлений `settings` — `max_ads` (сколько объявлений открыть, по умолчанию 40) и `pause_seconds` (пауза между запросами, 1 с); у `myrealty` ещё `max_pages`. Пауза в тестах подменяется: `MyrealtyAdapter(sleep=...)`, а `time.sleep` в `conftest.py` ничего не ждёт. Одно битое объявление пропускается, ни одного прочитанного — `ValueError`. `url` в `real_estate_am` — карта сайта: постраничный список там идёт через `/filtered-properties`, закрытый robots.txt.

`settings` определяет адаптер. Обычный ключ одной страницы — `url`. Поля `id` и `adapter` — строчные латинские буквы, цифры и `_`.

Порядок опроса задаёт `ordered_enabled_sources`: сначала `proxy_direct`, затем `official`, затем `third_party`, затем `statistics`; внутри вида меньший `priority`, при равенстве — порядок в JSON. Выключенный источник в этот список не входит. Сама политика (скачок 30%, `stale`, уведомление) — шов (c), её не дублировать в адаптере. Её считает `ubc.policy.choose_article`; issue с меткой `data-alert` открывает и закрывает `ubc.alerts.sync_alerts`.

Примечание записи (`note`) читает посетитель сайта: какая цена, из какого документа, какая оговорка. Как устроен разбор, номеров тикетов и фразы `paid_data_note` в нём нет: фразу добавляет сайт по пометке. То же относится к `source` нормы: на сайт попадает он, а `note` нормы — нет.

Дата, которую документ печатает вне текстового слоя (КРОУ Армении), записана в `settings.effective`: `prices` (все цены в том порядке, в каком их читает адаптер), `valid_from`, `basis`. Запись действует, только пока прочитанные цены совпадают точно; иначе датой служит дата создания PDF, и новую дату надо прочитать глазами и дописать. Тариф воды Еревана — скан, цифры года переписаны вручную в `ubc/adapters/yerevan.py` (`_RECORDED_WATER`, `_RECORDED_WATER_YEAR`): за месяц другого года источник отказывает, пока решение того года не переписано.

Категория записи следует из статьи (`ITEM_CATEGORY`): обслуживание дома — `housing`, остальные статьи счёта — `utility`, курс и градусо-сутки — `context`. Пометки (`fixed`, `norm_based`, `statistics_estimate`, `third_party`, `llm_extracted`, `stale`) ставятся при расчёте, не адаптером.

Курс: `item = fx`, `city = "all"`, `value` — сколько местной валюты за 1 евро, `unit` ровно `<валюта>/EUR` (для AMD это `AMD/EUR`). Градусо-сутки месяца: `item = hdd`. Градусо-сутки отопительного года (знаменатель раскладки нормы): `item = hdd_annual`. Оба с указанным городом, `unit = HDD_UNIT` (`K*day`) и без валюты. Месяц запроса берётся из `ctx.period`, не из `valid_from`: `valid_from` — с какой даты действует тариф или к какому месяцу относится уже посчитанная сумма. `valid_from` строкой `YYYY-MM` сохраняется как первый день месяца.

## Месячный прогон

`run_month(MonthOptions)` делает всё по порядку. Новый адаптер или город подхватывается из `data/cities/`, код прогона для этого не меняют. Фетчер, транспорт прокси, клиент GitHub и шаг домов (`house_step`) передаются снаружи: в тестах — фикстуры и заглушки.

1. Каждый источник статьи из `eligible_sources` вызывается через `RecordingFetcher`. Исключение адаптера превращается в `SourceAttempt` (`invalid` для `ValidationError`, иначе `error`), прогон не роняет.
2. `choose_article` сравнивает с прошлым `ActingValue` из `data/state`. Запись, которая закончилась раньше конца месяца, считается отказом источника: остаётся прошлое значение с пометкой `stale`.
3. Уведомления уходят до расчёта, поэтому доходят и тогда, когда сборка потом упала. Без `GITHUB_TOKEN` и `GITHUB_REPOSITORY` их нет. Курс и градусо-сутки политику не проходят, но об отказе тоже уведомляют. Отказ сайта объявлений — только предупреждение в логе.
4. `enrich_candidates` и `pin_houses`, затем девять ячеек `calculate_cell`. Открытые данные прогон не роняют и не тормозят: любой их сбой — предупреждение, а на город отведено пять минут (`open_data_budget_s`).
5. Файлы пишутся в самом конце, когда посчитаны все запрошенные города. `PublicationError` — не записано ничего.

**Несколько записей одной статьи.** Статью в политике представляет первая запись из тех, что попадают в счёт, остальные сравниваются вместе с ней. Из записей одной меры (`AMD/kWh`) с одинаковым `valid_from` остаётся первая. Поэтому адаптер ставит первой цену обычного бытового потребления: у PSRC это дневной тариф, а ночной, который идёт второй записью, лежит в `data/normalized` и в счёт не входит. Слагаемые одной цены (снабжение и распределение) адаптер складывает сам.

**Даты тарифа.** Новый тариф дописывается в `history`, старый остаётся со своими датами; более раннее значение закрывает только дни до начала более нового. Самая ранняя известная цена, которая начинается внутри месяца, берётся с первого числа, а строка показывает дату источника и примечание. Если известная цена начинается позже месяца — сборка падает.

**Что роняет сборку.** Ошибка `calculate_cell`; у города с заполненной ячейкой — нет курса, нет градусо-суток или статья с включённым источником не дала тариф и прошлого значения нет. Не роняет: город без подключённых тарифов (девять пустых ячеек и настоящий курс; без курса его месяц пропускается) и дом, чей тип отопления в городе ещё не тарифицирован (пустая ячейка с причиной).

Курс и градусо-сутки берутся из первого источника, давшего запись с `valid_from` в первый день месяца: сегодняшний список НБ Сербии среднемесячный курс не заменяет.

`--item` собирает одну статью, остальные берёт из `data/state` (с пометкой `stale`, если они сохранены за более ранний месяц), дома — из `data/houses`. Пересчёт месяца старше сохранённого состояния берёт тарифы из истории, а сегодняшний ответ источника — только если история тот месяц не закрывает. Ни состояние, ни дома он не меняет.

Workflow `monthly.yml` запускается 7-го числа: архив Open-Meteo отстаёт примерно на пять дней, а месяц или отопительный год с пропущенными днями — отказ источника. Запрос всегда с `models=era5`: без него архив отвечает другой моделью. Он коммитит `data/` и вызывает `pages.yml`: пуш с `GITHUB_TOKEN` сам его не запускает. На Pages попадает только то, что собрал `ubc.site_bundle`.

## Схемы

Лишние поля запрещены (`extra=forbid`). Неверное значение роняет загрузку.

- **Нормализованная запись** — город, статья, категория, значение, единица, валюта, ступени, действует с/по, источник (тип, URL, когда получено), способ получения (`regex` / `llm_text` / `llm_vision` / `api`), уровень надёжности, примечание. Ступени возрастают, открытая граница только у последней. Единицы, которые читает `calculate_cell`, перечислены в `GLOSSARY.md` (раздел «Нормализованная запись»). Пометки `stale` передаются в `extra_marks`: их ставит политика выбора, не адаптер.
- **Кандидат дома** — id, город, адрес и координаты, отопление как на сайте и приведённое, год или диапазон или серия, новостройка, этаж и этажность, удобства комплекса (`Amenity`), голые стены (`unfinished`), площадь, жилищные сборы (сумма, валюта, период, за м² или за квартиру), цена за м², вид квартала из открытых данных, ссылка, когда видели. Пустые факты с сайта остаются `null`.
- **Закреплённый дом** (`PinnedHouse`) — уже разложен по классу и типу отопления: сборы (список, может быть пустым), ссылка на объявление (остаётся и после его снятия), адрес и координаты если есть, `first_seen` / `last_seen`. Его пишут #36 и читает расчёт ячейки #21.
- **Конфигурация города** — валюта, координаты, текст пометки о платных данных, восемь статей с упорядоченными источниками, сайты объявлений, правила домов (`house_rules`), открытые данные (`open_data`), источники курса и градусо-суток.
- **Эталонная квартира** — 2 комнаты, 60 м², 2 жильца. Другие числа схема не примет. Нормы расхода лежат в `data/reference.json`, не в коде: отопление на м² по классу (TABULA для PL, RS, DE; Всемирный банк для GE; у Еревана — проданный населению газ из Армстата, один и тот же для всех классов: по типам домов он не разделён, придумывать отношение нельзя), электричество на человека, вода Белграда — норма Infostan без счётчика. Для Лиссабона отопление электричеством — 230 кВт·ч на жильё за зиму (INE ICESD 2020), не строка TABULA. Норма газа без типа отопления — плита и горячая вода: в ячейке с котлом это строка `gas`, а отопление — отдельная строка `heating` по тому же тарифу (ступени — от суммы), как у электрического отопления. Без такой нормы котёл даёт одну строку `gas`. `applies_to` перечисляет столбцы нормы, пустой — все: у Еревана плита и вода на газе есть только у `gas_boiler`, в квартире с электрическим отоплением они ничем не подтверждены.
- **Контракт сайта** (`CityMonth`) — JSON на город и месяц: курс и дата обновления, ровно 9 ячеек. У заполненной ячейки итог в евро, подсуммы жилищных и коммунальных, разбивка (источник, дата, пометки) и дом. Пустая ячейка без сумм, со статусом `empty` и причиной.

Координаты в `data/cities` — те же, что у градусо-суток (Open-Meteo). Новый город — новый JSON, без правок расчёта, плюс значение в `CityId` и подписи.

## Слой получения содержимого

`FixtureFetcher` в тестах и `HttpFetcher` в живом запуске. Оба умеют `fetch_bytes`, `fetch_text`, `render_html`, `pdf_to_text`.

`HttpFetcher` ходит по HTTPS с проверкой сертификата и своим User-Agent. Curl вызывается только если рукопожатие или соединение оборвалось (TLS, таймаут, отказ соединения, DNS) и **без** отключения проверки TLS. Ответ HTTP с кодом ошибки и любое другое исключение curl не запускают. `render_html` — headless Chrome `--dump-dom` для страниц, которые без JS пустые. Chrome ищется так: `chrome_bin`, переменная `CHROME_BIN`, `PATH`, обычные каталоги Windows; профиль каждый раз временный. `pdf_to_text` — `pdftotext` (poppler или xpdf); PDF передаётся файлом, раскладка строк у них разная, поэтому адаптер не привязывает число к соседней подписи. Программа, которая не запустилась или зависла, — `FetchError`. Это не обход защиты от роботов: ответ-блокировка означает, что источник не отдал данные. В тестах `conftest.py` закрывает и сокеты, и запуск `curl` / Chrome.

## Защита от роботов, прокси, ИИ

Защиту от роботов не обходить (Cloudflare-челлендж, сайты, которые прямо запрещают сбор). Такой источник — отказ, дальше идёт следующий по приоритету.

Прямой сбор через прокси и ИИ-разбор в MVP выключены и в сеть не ходят. Вид `proxy_direct` и способы `llm_text` / `llm_vision` уже есть в схеме. Политика выбора (шов (c)) берёт список из `eligible_sources`: без секретов эти источники выпадают, даже если в JSON стоит `enabled: true`, и опрос идёт дальше. `ordered_enabled_sources` по-прежнему смотрит только на флаг `enabled`.

### Как включить прокси

Секреты процесса: `PROXY_HOST`, `PROXY_LOGIN`, `PROXY_PASSWORD`, `PROXY_COUNTRY`. Пустая строка считается отсутствием секрета. Пароль не попадает в текст ошибок.

Источник — тот же `adapter`, что у страницы, вид `proxy_direct`. Надёжность берётся у страницы: прокси её не меняет. `settings.country` перекрывает `PROXY_COUNTRY`.

```json
{
  "id": "lisbon_sewage_proxy",
  "adapter": "lisbon_sewage",
  "kind": "proxy_direct",
  "priority": 0,
  "enabled": true,
  "reliability": "official",
  "settings": {"url": "https://example.pt/tariff", "country": "pt"}
}
```

Перед `collect` подставить транспорт: `fetcher_for_source(source, direct, SecretConfig.from_env(), transport)`. `transport` — объект с `fetch_bytes(url, *, proxy, user_agent)`. Без секретов функция бросает `SourceUnavailable`. Если транспорт не передан, встроенная заготовка бросает `FetchError` и соединение не открывает. `render_html` через прокси заготовка не делает. `pdf_to_text` забирает байты у транспорта и снимает текст локальным pdftotext.

### Как включить ИИ-разбор

Адаптер реестра — `llm_extract`. Секрет `LLM_API_KEY`. Без ключа, без сохранённого ответа и без переданного клиента `collect` бросает `SourceUnavailable`.

Настройки источника: `url` документа, `item` статьи, `mode` = `text` или `vision`. Ответ модели — JSON без лишних полей: `value`, `unit`, `valid_from`, `valid_to`, `consumer_category` (`household` или `бытовые`), `quote`, `tiers` (`up_to`, `value`).

Проверки. Провал — `ExtractionRejected`, поле `rule`:

| `rule` | Условие |
| --- | --- |
| `unit` | Единица не из списка «валюта, `local` или `tetri` / мера» (`kWh`, `m3`, `m2/month`, …) |
| `range` | Значение (и цена ступени) вне широкого диапазона города. Это отсев мусора, не тариф |
| `date` | `valid_from` позже чем на 3 календарных месяца после последнего дня месяца сбора (`ctx.period`) |
| `category` | Категория потребителя не бытовая |
| `quote` | Цитата пустая. В режиме `text` её нет в тексте страницы. Для скана (`vision`) достаточно непустой цитаты |
| `tiers` | Границы ступеней не возрастают или цена следующей ступени ниже предыдущей |
| `schema` | Ответ не совпал со схемой |

В тесте ответ подменяется файлом: `settings.model_response_url` читается тем же `FixtureFetcher`. Свой клиент — `LlmExtractAdapter(client=...)`, метод `complete(LlmRequest) -> str`. Живого HTTP-клиента модели нет: ключ делает источник доступным для политики, но без своего `LlmClient` заготовка отказывается звонить в сеть.

### Пометка о доплате

`paid_data_note(city, reliability)` возвращает `city.paid_data_note` для надёжности `statistics` и `third_party`, и `None` для `official`. Текст и сумма в долларах берутся из файла города. Фразу показывают у оценки по статистике, у стороннего сайта и у цифры, которая заменяет выключенный ИИ-разбор.

## Команды

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
ruff check .
ruff format --check .
pytest
python -m ubc.pipeline --check
python -m ubc.pipeline --city yerevan --period 2026-10
python -m ubc.pipeline --run --city yerevan --period 2026-10 --dry-run
python -m ubc.site_bundle _site
```

`python -m ubc.pipeline --period YYYY-MM` без `--run` проверяет JSON, печатает включённые источники и передаёт месяц в `collect_contexts`. Он не открывает сеть и не считает ячейки.

С `--run` команда ходит в сеть и пишет `data/`. Без `--period` — прошедший месяц. `--dry-run` считает, но ничего не пишет и не отправляет; `--no-alerts` только не трогает issues; `--data-root` меняет каталог. Код 1 — не опубликовано, причины в stderr. Живой вывод с локальной машины не коммитить: данные коммитит бот Actions.

Сайт — `index.html` и `site/`. Он сам не обходит каталог: читает `data/site-index.json`, затем каждый путь из него. В индекс входят `data/examples/<city>-<YYYY-MM>.json` (пометка «пример») и `data/<city>-<YYYY-MM>.json`, которые позже пишет конвейер. Файл конвейера заменяет пример того же города и месяца. После нового снимка индекс пересобирается командой `python -m ubc.site_index`. `reference.json`, `data/cities/`, `data/raw/`, `data/normalized/`, `data/state/` и `data/houses/` в индекс не входят.

Суммы в данных всегда в евро. Переключатель валюты (€, ֏, ₽) пересчитывает их на странице по `data/display-rates.json`: курс евро и рубля к драму одним запросом к ЦБ Армении, его делает `run_month` через `MonthOptions.display_rate`. Отказ курса прогон не роняет: остаётся предупреждение, а сайт за месяц без курса показывает евро. Итог в драмах и рублях — сумма округлённых строк.

Вкладка «Источники и расчёт» читает `data/methodology.json`, когда её открыли. Файл собирает `ubc.site_bundle`; в git его нет, для локальной страницы — `python -m ubc.methodology`. Фактов в `site/sources.js` нет. Что держать в порядке при правках:

- у нового источника и сайта объявлений — `title_ru`, у источника ещё `reading` (`page`, `pdf`, `api`, `scan`, `manual`); если `url` — адрес API, то `page_url` со страницей для человека. На расчёт эти поля не влияют;
- `limits_ru` города — что не учтено именно в нём; правится вместе с источником или нормой, о которых там сказано;
- меняются правила расчёта, выбора домов, политики или расписания — правится общая часть в `ubc/methodology.py`.
